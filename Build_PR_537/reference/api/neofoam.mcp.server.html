neofoam.mcp.server¶

The MCP server — a module-level mcp (FastMCP v3) with every tool/resource.

Built with the FastMCP decorator pattern at module level: mcp is the server, each @mcp.tool / @mcp.resource is a thin wrapper over the plain logic in neofoam.mcp.tools. Import it directly — from neofoam.mcp.server import mcp. Every tool takes a solver argument (a registered spec name, default incompressibleFluid) and resolves it per call, so the server is solver-agnostic; an unknown name raises ValueError (surfaced as a tool error). The neofoam://{solver_name}/… resources resolve by name the same way.

Filesystem tools (read_case/load_case/save_case/validate_case/ case_patches/import_geometry/build_mesh_inputs/save_preprocess/ save_post) confine their path arguments under a workspace root when one is configured (configure_root(), mcp serve --root, or NEOFOAM_MCP_ROOT): paths must then be relative and any escape is rejected as a tool error. With no root set, absolute paths are allowed — for trusted, local (stdio) use only.

This module (and neofoam.mcp.app) are the only ones that import the mcp extra (fastmcp / fastapi); without it, importing raises a plain ImportError — install with pip install 'neofoam[mcp]'.

neofoam.mcp.server.DEFAULT_SOLVER = 'incompressibleFluid'¶

Default solver argument for the tools (the only registered spec today).

neofoam.mcp.server.INSTRUCTIONS = 'NeoFOAM case-authoring server: author + validate an OpenFOAM case, then hand off to\nthe CLI to run. Intended tool order:\n\n  1. workspace_info      — learn the path rules (see "Workspace" below) first.\n  2. list_solvers / model_catalog / list_configs / config_schema — introspect the\n     solver\'s models and each config\'s JSON Schema + defaults. IMPORTANT:\n     model_catalog lists only *model-owned* configs; a solver also has\n     always-declared configs (transportProperties/turbulenceProperties/gravity) that\n     no model owns. list_configs marks those with origin == "solver" — author every\n     origin=="solver" (physics/time) and every required-model config, or the run\n     fails to find e.g. constant/g or constant/transportProperties. case_spec_schema\n     describes the save_case envelope; manifest_schema describes import_geometry\'s\n     manifest — so both authoring payloads are self-describing (no source reads).\n  3. import_geometry      — stage geometry (writes <case>/manifest.json, the geometry\n     hand-off contract; required keys geometry_source/bbox/location_in_mesh/\n     length_scale — see manifest_schema); case_patches reads the patch names + roles\n     back; build_mesh_inputs renders the mesh dicts from the manifest. To add setFields\n     or otherwise change the pipeline, save_preprocess; the region selectors and their\n     schemas come from post_catalog family "Node", the setFields YAML schema from\n     config_schema("set_fields_config").\n  4. save_case            — author the case (validated against the solver\'s model).\n  5. post_catalog / save_post — declare in-situ post-processing tables. post_catalog\n     lists every registered source/node/writer/write control with its JSON Schema —\n     the only place the accepted "type" strings appear, because the\n     post_process_config schema keeps those four mappings open; save_post validates\n     a spec against them and writes <case>/system/postProcess.yaml. Optional: a case\n     with no spec file simply post-processes nothing.\n  6. validate_case        — static pre-flight (completeness + BC/mesh-patch checks).\n\nWorkspace: when the server is started with a root (`mcp serve --root` /\nNEOFOAM_MCP_ROOT), every path argument must be a RELATIVE path under that root;\nabsolute paths and `..` escapes are rejected. With no root, absolute paths are\nallowed (trusted local/stdio use). Call workspace_info to see which applies.\n\nRunning is NOT this server\'s job — it is the CLI\'s: `neofoam preprocess <case>`\nbuilds the mesh (blockMesh/snappy) and `neofoam solver <name>` runs the time loop.\ntool_catalog only *describes* those preprocessing tools; it does not execute them.\nFor BC/mesh-patch checks, run validate_case AFTER `neofoam preprocess` builds the\nmesh (or rely on the manifest patches import_geometry staged).'¶

Onboarding string so a fresh client is self-orienting (F7): intended tool order, the workspace rules, and that running is the CLI’s job (not this server).

JSON Schema of the save_case envelope + the config keys it accepts.

neofoam.mcp.server.config_schema(name: str, solver: str = 'incompressibleFluid') → ConfigSchema[source]¶

JSON Schema + rjsf ui-schema + defaults for one config class of solver.

neofoam.mcp.server.configure_root(root: str | Path | None) → None[source]¶

Set the workspace root confining every filesystem tool’s case_dir/target_dir.

Once set, path arguments must be relative and are rejected (as a tool error) if they escape root — the trust boundary for an untrusted MCP client. None clears it, restoring the trusted absolute-path behavior for local stdio use.
